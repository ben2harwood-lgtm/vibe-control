What happens when you run it

  1. You say what you want, in a sentence or a file.
  2. It shows you the plan and, if your tests already fail, tells you so before anything starts.
  3. Claude Code builds it in a separate copy. It can read and edit files there and nothing else: no commands, no writing outside that copy.
  4. The result is frozen. Every later step works on that exact result.
  5. Your own tests run on the frozen result.
  6. A second, fresh Claude run reviews it with read-only tools and gives a plain verdict. It is the same model family, not an independent reviewer, and every screen says so.
  7. You approve by typing a short code that names the exact result. No flag or setting can approve for you.
  8. You get a new branch in your own repository and a receipt. Vibe Control never pushes anywhere; you push and open the pull request yourself.

In our runs the whole thing took 20 to 50 seconds.

What it leaves alone

Your working files, your current branch, and anything untracked or ignored, such as node_modules and .env files. They are not copied, read or changed.

What it is not

  • Not a security product. We make no protection promises.
  • Your tests are not sandboxed. They run on your machine as you, exactly as when you run them yourself, on code Claude wrote. Read the diff.
  • The reviewer is a second Claude session, not a different company's model.
  • A passing check does not prove your tests ran. Vibe Control fixes what your top-level npm, yarn or pnpm test script says before the change and stops if the change edits it. Scripts in another folder's package.json are not covered. A change can still alter how your tests behave in other ways: an .npmrc file, a test-runner settings file, the script your test command calls, or the test files themselves. It lists every changed file. Read that list before you approve.
  • Trust the last block on screen. The reviewer's words and your test output appear on marked lines. In a narrow window a very long line can wrap without its marker. The changed files, the test result, the verdict and the code to type are always printed last, right above the question.

Fair questions

Can I read the code? Yes. The download is plain source. The licence key is an honest-user gate, not copy protection. You type the key when asked; it is not shown and never goes on the command line.

Does it send my code anywhere? Vibe Control does not send your code. Licence requests send your key and activation details to the licence service: the fixed name “Vibe Control” when activating, or the activation ID when checking or deactivating. Claude Code talks to Anthropic under your own Claude set-up. Your check command runs on your computer without a sandbox and may also use the network.

What if I stop it half way? Ctrl-C, or closing the terminal window, stops the run, ends what it started and delivers nothing.
